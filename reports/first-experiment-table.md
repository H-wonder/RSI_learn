# 第一张实验表（60 题，max effort）

> 60 题 = 6 域 × 10 题，固定间隔 `0,11,...,99`。
> 主结果：`results/medium-max/`；默认 effort 的旧 60 题保留为 A 组对照。
> 成本是框架上界（所有 input 按原价）；cached input 占 92.6%，实际账单可能低很多。

## 怎么读这张表

- **Model / Toolset / max_steps / reasoning effort / API**：复现条件；少一项就不可比。
- **通过率**：主指标，所有计分断言都过才算 1；对应官方 `task_completed_correctly`。
- **部分分**：诊断指标，用来区分“完全不会”和“差一点”；不能代替通过率。
- **n = 10/域**：样本很小，分域差异要结合 95% CI 看，不能当总体结论。
- **平均步数 / 成本**：效率与可复现性；防止把“靠堆预算”误读成“模型更强”。
- **P4a / P4b**：P4 拆成“资格筛选”和“分支路由”；两类失败模式不同，不能合并看。

## 关键观察

1. **max effort 显著提升**：33.3% vs 默认 11.7%；McNemar p=0.00098；
   14 题从失败变通过，1 题从通过变失败（`finance.revenue_recognition`）。
2. **P4a 提升最大**（18.8% → 56.2%）：规则/资格类任务最吃推理预算。
3. **P4b 从 0% → 33.3%，部分分 0.797**：路由类“差一点”的比例仍然高。
4. **P2 仍只有 10%**：多跳检索的瓶颈不是预算，而是数据源/实体解析。
5. **P9 仍 0%，平均 29 步**：长链任务需要显式收尾/检查点，而不是更多 token。
6. **M4 + M6 = 60% 的失败**：先做 FinalActionNode + VerifierNode，
   比全流程重写更划算。
7. **成本**：上界 $120.41；按 cached 10% 估算约 $34.63；报告里写区间。
8. **refusal**：`operations.drive_slack_dock_schedule` 被安全分类器中断，按 0 分；
   单独重跑与敏感性分析见 `results/refusal-retry/`。
